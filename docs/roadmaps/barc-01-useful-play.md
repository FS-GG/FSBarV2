## Contract decisions for the first join

The named **BARC parent integrator** owns shared interfaces, generated bindings, build manifests, runtime installation, PR admission and final source/native evidence. One small local interface commit is consumed by all lanes; it lands with substantive implementation. It is not a planning PR.

1. Preserve frozen legacy coordinator files and preview ABI/projection semantics. Extend the additive live contract with an explicit negotiated tactical capability revision/profile; old live peers retain their `.4` subset and explicitly refuse new families. Keep uint64 lifetimes/revisions lossless, presence-bearing zero IDs valid, and private IDs opaque. Do not relabel old `.4` artifacts as new tactical artifacts.
2. Publish native-derived, content-bound unit/feature definitions and per-owned-unit command descriptors, including build options, footprints, permitted parameter shapes, disabled state and bounded costs/progress where supported. Bind engine/game/content identity and definition/capability revision into use and cache validity. Use bounded pages/chunks within existing 64 KiB frames, with complete-set identity and explicit incompleteness; never truncate a catalogue and call it complete. Unknown/missing definitions remain unknown and cannot become build ID zero or invented classes. Native thread snapshots produce data; network threads consume immutable copies.
3. Add typed Build, Guard, Repair, ReclaimUnit/Feature/Area, FactoryProduce, SetRally, QueueEdit and selected game-command intentions. Inputs carry actor sets, typed target, semantic queue policy and required definition/queue revision. No arbitrary Lua, cheat/admin commands, raw INTERNAL options, or unrestricted numeric custom-command escape hatch. Negative build IDs and engine option bits remain native translation details.
4. Keep construction and factory production distinct. Placement uses actual footprint/facing/map/terrain/buildability semantics; it is a preview/preflight, never a promise of future success. Production count expands with a declared bound and child identities; factory queue and rally queue are distinguished by engine semantics. Queue operations include replace/append, insert/remove, repeat and reject-if-busy with individually tested supported semantics. Edits bind actor lifetime, native queue revision and native tag; no stale index cancellation. Recheck on the engine thread immediately before mutation. Never implement reorder as an unfenced clear-and-replay shortcut.
5. Extend target lifetime/eligibility to friendly guard/repair targets and features. Current known feature identity and visibility rules must come from the selected engine perspective. If polling cannot detect destroy/reuse, qualify lifecycle callbacks or issue conservative observation-bound feature tokens whose final validation cannot target a replacement. Native actors, targets, build options, queue revision, authority, freshness and game-command capability all get final checks.
6. Expose economy values with presence, units, perspective and sample frame. Use direct current resource callbacks rather than cached strategy-manager values whose updates may be disabled. Show absent income/usage as unavailable; distinguish resource shortage, placement refusal, disabled command, engine dispatch and later observed progress. Preserve atomic broker preflight where possible, but several native effects are not a transaction. Partial children and unknown outcomes remain visible; unknown outcomes never auto-retry.
7. Select BAR construction priority as the first custom-command family and cloak desire as the second candidate, using actual selected-game command definitions, per-unit descriptors and observable current mode. Existing constants `34571`/`37382` are discovery clues, not authority. Pin meanings/ranges only after checking the selected content. If either is unavailable in that runtime, choose another actual bounded observable BAR command during `.5a` and record why; do not silently omit custom-command acceptance or claim all commands supported.
